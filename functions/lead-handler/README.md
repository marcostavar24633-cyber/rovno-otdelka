# Lead handler — «Ровно»

Заготовка HTTP-обработчика для Yandex Cloud Functions (Node.js). Сейчас это **не подключённый приёмник**: пока не настроен внешний получатель заявок, функция намеренно возвращает 503 и не сообщает об успешной отправке.

## Переменные окружения функции

- `CORS_ORIGIN` — точный origin сайта. По умолчанию `https://marcostavar24633-cyber.github.io`. Если появится собственный домен, указать его отдельно.
- `LEAD_DELIVERY_URL` — HTTPS URL российского сервиса/CRM/почтового шлюза, который принимает POST JSON по описанному ниже контракту.
- `LEAD_DELIVERY_TOKEN` — секрет для авторизации у получателя. Хранить только в Secret Manager / переменных окружения функции, не в Git.

## Контракт получателя

Функция отправляет POST с `Content-Type: application/json` и `Authorization: Bearer <token>`. Тело содержит `source`, `form`, `name`, `phone`, `type`, `object`, `area`, `calc`, `estimate`, `quiz` (ответы квиза), `page`, `consent`, `receivedAt`. Заголовок `Idempotency-Key` содержит clientRequestId формы или request ID шлюза. Получатель должен поддерживать этот ключ для дедупликации и отвечать HTTP 2xx только после того, как принял заявку в свою систему.

Перед подключением нужно проверить договор/условия обработки персональных данных, фактическое расположение базы и все места хранения/резервирования. Само размещение функции в российском регионе не гарантирует соответствие требованиям 152-ФЗ, если получатель или другие участники цепочки обрабатывают данные за рубежом.

## Развёртывание и ограничения

1. Создать функцию в российском регионе Yandex Cloud и выбрать поддерживаемый Node.js runtime.
2. Загрузить `index.js`, указать точку входа `index.handler`.
3. Настроить переменные/секреты, только после выбора и проверки получателя.
4. Настроить API Gateway или HTTP-триггер и ограничение частоты запросов на уровне шлюза.
5. Проверить OPTIONS, POST, ошибки получателя и резервный сценарий на сайте.

Функция проверяет метод, JSON content-type, размер тела (16 KiB), origin, имя, телефон и согласие. Скрипт сайта добавляет поле-honeypot `website` динамически ко всем трём формам. Это базовая антиспам-мера, но не замена CAPTCHA или ограничению частоты на API Gateway.

Внутри функции нет постоянного хранилища: надёжный rate limit и гарантированная дедупликация здесь не реализованы. Заголовок Idempotency-Key передаётся по request ID шлюза, если он доступен; получатель должен поддерживать идемпотентность. Не логируйте персональные данные.
